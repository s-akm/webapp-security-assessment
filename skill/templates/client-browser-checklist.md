# ブラウザでの確認のお願い

このシートは、**セキュリティ評価のうち、評価者側では実施できない確認**をお願いするためのものです。

ログインが必要な画面の確認は、評価者がアカウントをお預かりして代行することを避けています。
お手元で操作していただき、**見えたものをそのまま記入**してください。

- 所要時間の目安: 30〜45 分（項目の数による）
- 必要なもの: 普段お使いのブラウザ（Chrome / Edge / Safari のいずれか）
- **判断は不要です。** 「良いか悪いか」ではなく、**見えたとおり**をご記入ください

---

## 記入欄（最初に）

```
サービス名:
確認した画面の URL（トップページ）:
実施日時:
使ったブラウザの名前と版（例: Chrome 140）:
使ったアカウントの種類（例: 一般の利用者 / 管理者 / 試験用）:
```

---

## はじめに（共通の準備）

**開発者ツール**を使います。次のキーで開きます。

| | 開き方 |
|---|---|
| Windows | `F12` または `Ctrl` + `Shift` + `I` |
| Mac | `Command` + `Option` + `I` |

Safari の場合は、先に「Safari →設定→詳細→**Web デベロッパー用の機能を表示**」を有効にしてください。

**⚠️ 作業中のお願い**

- **フォームの送信ボタンは押さないでください。** 問い合わせや申し込みが実際に飛んでしまいます
- 購入・予約・退会・削除の操作もお控えください
- 迷ったら**押さずに、その旨をご記入**ください
- **値（長い英数字の文字列）は書き写さないでください。** Cookie やトークンの値が入っています

## 1. ログイン情報がどこに保存されているか 〔09 の 2 節〕

**やること**

1. いつもどおりログインする
2. 開発者ツールを開く
3. **Application**（Safari は**ストレージ**）タブを開く
4. 左側の **Local Storage** → サイトの URL を選ぶ
5. **左側に並んでいる「キー」の名前だけ**を書き写す
6. 左側の **Cookies** → サイトの URL を選び、名前に token / session / auth / sb- などが含まれる行について、
   **名前と、右のほうにある HttpOnly・Secure・SameSite の列**を書き写す

**記入欄**

```
Local Storage に並んでいた名前:
（例: authToken, theme, user_id ...）


Cookie（名前 / HttpOnly の印 / Secure の印 / SameSite の列の表示）:
（例: session_id / ✓ / ✓ / Lax 　　 例: auth-token / 空欄 / ✓ / 空欄）


□ 名前に token / session / auth が含まれる Cookie は無かった
```

**⚠️ 値（Value の列の長い文字列）は書き写さないでください。** 名前と印だけで判断できます。
SameSite の列が**空欄**なら、「空欄」とお書きください（空欄であること自体が確認の結果になります）。

---

## 2. ログアウトした後に、戻るボタンで見えてしまわないか 〔09 の 6 節〕

**やること**

1. ログインして、**お名前や連絡先が表示されている画面**を開く
2. **ログアウト**する
3. **1 分以内に**、ブラウザの**戻るボタン**を押す

**記入欄**

```
戻るボタンを押した後、さっきの画面はどう見えましたか:
□ 個人情報がそのまま表示された
□ 一瞬表示されてから、ログイン画面に切り替わった
□ すぐログイン画面になった（何も見えなかった）
□ その他（　　　　　　　　　　　　　　　　）

ログアウトしてから戻るボタンを押すまでの時間: 約　　秒
```

共用のパソコンで使われる可能性がある場合、ここは重要な確認になります。
ブラウザの種類や版で結果が変わることがあるため、最初の記入欄のブラウザの名前と版も必ずご記入ください。

---

## 3. ログアウトしても、まだデータが取れてしまわないか 〔09 の 7 節〕

ログアウトした後に画面を開き直しても、ブラウザがログイン情報を捨てているため、この確認にはなりません。
**ログアウトの前に記録した通信を、ログアウトの後にもう一度送る**ことで確かめます。
端末（Mac は「ターミナル」、Windows は「コマンドプロンプト」）を使います。難しければ「未実施」で構いません。

**やること**

1. ログインし、開発者ツールの **Network**（ネットワーク）タブを開いた状態で、一覧や詳細などデータが表示される画面を開く
2. Network タブに並んだ通信のうち、データを取っているもの（名前に `api` や画面の名前が入っているもの）を 1 つ選び、
   右クリックして **「Copy as cURL」**（Safari は「cURL としてコピー」、Windows は **「Copy as cURL (cmd)」**）を選ぶ
3. コピーした文字列を、お手元のメモ帳に貼り付ける
4. **ログアウト**する
5. 端末に、貼り付けた文字列の**末尾に次を足して**実行する（Windows は `/dev/null` を `NUL` に置き換える）

```
 -s -o /dev/null -w "%{http_code}\n"
```

6. 表示された **3 桁の数字**を記入し、メモ帳の内容は削除する

**⚠️ コピーした文字列には、ログイン中の情報がそのまま入っています。評価者にも送らないでください。** 記入していただくのは 3 桁の数字だけです。

**記入欄**

```
表示された数字（例: 200 / 401 / 302）:
ログアウトしてから実行するまでの時間: 約　　分
□ 未実施（理由: 　　　　　　　　　　　　　）
```

## 4. 権限の無い画面に入れてしまわないか 〔09 の 3 節〕

**管理者用の画面がある場合のみ**お願いします。管理者アカウントをお持ちでない方の視点で確認します。

**やること**

1. **一般の利用者アカウント**でログインする（管理者ではないアカウント）
2. 開発者ツールの **Network**（ネットワーク）タブを開く
3. 管理画面の URL を、アドレスバーに直接入力して開く

**記入欄**

```
画面の見え方:
□ 管理画面が普通に表示された
□ 一瞬中身が見えてから、別の画面に切り替わった
□ 最初から入れなかった

Network タブで、赤くない（成功した）通信の中に、
管理用のデータらしきものは含まれていましたか:
□ 含まれていた　　□ 含まれていなかった　　□ 分からなかった
```

2 番目と 3 番目は、画面上は同じに見えても中身が違います。**Network タブを見ていただくのはこのためです。**

---

## 5. 他の方のデータが見えてしまわないか 〔09 の 3 節〕

**アカウントを 2 つご用意いただける場合のみ**お願いします。難しければ「未実施」で構いません。

**やること**

1. アカウント A でログインし、データの詳細画面を開く。**URL に含まれる番号や ID を控える**
2. ログアウトし、**アカウント B** でログインする
3. 控えた URL を開く

**記入欄**

```
□ アカウント A のデータが見えた
□ 見えなかった（エラー / 一覧に戻された）
□ 未実施（アカウントを 2 つ用意できなかった）
```

---

## 6. 入力した文字がそのまま画面に出ないか 〔09 の 5 節〕

**やること**

検索欄や、入力内容が画面に表示される欄に、次の文字列を**そのまま**入力します。**送信ボタンは押しません。**
検索欄など、押さないと結果が出ない場合は、検索のみ実行してください。

```
SECTEST<b>1234</b>
```

**記入欄**

```
入力した文字は、画面にどう出ましたか:
□ 「SECTEST<b>1234</b>」と、記号も含めて文字のまま表示された
□ 「SECTEST1234」と表示され、「1234」だけが太字になった
□ 表示されなかった
□ その他（　　　　　　　　　　　　　　　　）

そのページの URL（個人を示す番号やメールアドレスが入っていれば、その部分は伏せてください）:
```

**これは動作を壊す操作ではありません。** 太字になるかどうかしか起きない文字列です。
良し悪しの判断は不要で、**太字になったかどうか**だけをご記入ください。

## 7. 即時に届く通知やチャットの通信 〔09 の 9 節〕

**チャット・通知・共同編集など、画面を開いたまま内容が自動で更新される機能がある場合のみ**お願いします。

**やること**

1. ログインし、開発者ツールの **Network** タブを開く
2. Network タブの上のほうにある絞り込みで **WS**（Safari は「WebSocket」）を選ぶ
3. 通知やチャットの画面を開き、表に出てきた行を 1 つ選んで、**Messages**（メッセージ）の欄を開く
4. しばらく待ち、流れてくるメッセージを**見るだけ**にする。**自分から送信はしない**
5. そのままログアウトし、同じ欄にメッセージが流れ続けるかを見る

**記入欄**

```
WS の行はありましたか:            □ あった　□ 無かった
行の名前（「?」より後ろは書かないでください）:

メッセージの中に出てくる "topic" "channel" "room" などの値の形
（数字は 0 に、英数字の長い並びは x に置き換えてください。例: room:0000 / user:xxxx）:

流れてきたメッセージに、ご自身以外の方の名前や内容は含まれていましたか:
□ 自分のものだけだった　□ 他の方のものも含まれていた　□ 分からなかった

ログアウトした後も、メッセージは流れ続けましたか:
□ 流れ続けた　□ 止まった　□ 分からなかった
```

**⚠️ メッセージの中身は書き写さないでください。** 形と、見えたかどうかだけで判断できます。

## 8. お支払いの画面で動いているプログラムの読み込み元 〔09 の 10 節〕

**カードでのお支払いがある場合のみ**お願いします。

**やること**

1. カード番号を入力する画面まで進む（**お支払いは確定しないでください**。カード番号も入力不要です）
2. 開発者ツールの **Network** タブを開き、絞り込みで **JS**（Safari は「スクリプト」）を選ぶ
3. ページを**再読み込み**する
4. 並んだ行の **Domain**（または URL の `https://` の後ろから最初の `/` まで）を書き写す。同じものは 1 回で構いません

**記入欄**

```
カード番号を入力する画面の URL（「?」より後ろは書かないでください）:

読み込み元の一覧（例: 自社のドメイン / 決済代行のドメイン / 計測サービスのドメイン）:


カード番号の入力欄は、決済代行の画面に移ってから表示されましたか:
□ 決済代行の画面に移った（アドレスバーのドメインが変わった）
□ 同じ画面の中に表示された
□ 分からなかった
```

## 9. 画面操作を記録するツールに、入力した文字が写っていないか 〔09 の 11 節〕

**画面操作を記録するツール（例: Microsoft Clarity、Hotjar、Sentry の Session Replay、LogRocket）を使っている場合のみ**、
**試験用のアカウント**でお願いします。

**やること**

1. 試験用のアカウントでログインし、次の文字列を**入力欄**（検索欄やフォームの欄）に入力する。**送信ボタンは押さない**
2. 試験用のアカウントのプロフィールなど、**画面に表示される欄**にも同じ文字列を入れて保存する（試験用のアカウントなので保存して構いません。
   本番の利用者のデータには入れないでください）

```
SECTEST-1234
```

3. 数分待ってから、ツールの管理画面で**ご自身の今の操作の録画**を探して再生する。**他の方の録画は開かないでください**
4. 目印の文字列が録画の中でどう見えたかを記入する

**記入欄**

```
ツールの名前:
入力欄に入れた文字は、録画でどう見えましたか:
□ 「SECTEST-1234」とそのまま見えた　□ 伏せ字（*** や ■■■ など）になっていた　□ 録画が見つからなかった
画面に表示される欄の文字は、録画でどう見えましたか:
□ 「SECTEST-1234」とそのまま見えた　□ 伏せ字になっていた　□ 録画が見つからなかった
```

## ご返送について

- **記入したこのシート**をお送りください
- 画面の写真を撮っていただける場合は、**個人情報の部分を隠して**からお願いします
- 「よく分からなかった」「途中で止めた」もそのままお書きください。**未確認であることが分かるほうが、確認したつもりで進むより安全です**
